# Лабораторная работа №1: Linear и Logistic Regression

Дисциплина: «Системы искусственного интеллекта».

Собственные реализации линейной и логистической регрессии на PyTorch.
Градиенты, обновление весов, train/validation/test split, заполнение пропусков,
стандартизация, one-hot кодирование и метрики реализованы самостоятельно.
Из sklearn используется только `metrics` для независимой проверки метрик.
Готовые слои, оптимизаторы и autograd в обучении не используются.
Краткий отчёт, графики, эксперименты и выводы находятся в `lab1.ipynb`.

## Состав проекта

| Файл | Назначение |
|---|---|
| `lab1.ipynb` | Воспроизводимый эксперимент и отчёт |
| `models/linear_regression.py` | Линейная регрессия, MSE и полный градиентный спуск |
| `models/logistic_regression.py` | Логистическая регрессия, sigmoid и устойчивая BCE |
| `preprocessing.py` | Предобработка отдельно для каждого датасета |
| `split.py` | Обычное и стратифицированное разбиение по индексам |
| `evaluation.py` | Собственные метрики регрессии и классификации |
| `data/day.csv` | Bike Sharing Dataset |
| `data/train.csv` | Размеченные данные Spaceship Titanic |
| `requirements.txt` | Прямые зависимости проекта |

## Установка и запуск в Windows

Открыть папку проекта в PyCharm. В терминале этой папки:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Если окружение уже создано и работает, пересоздавать его не нужно.
Выбрать `.venv/Scripts/python.exe` как интерпретатор проекта и ядро ноутбука.
Открыть `lab1.ipynb` и выполнить Restart Kernel and Run All Cells.
Запускать из корня проекта: относительный путь `data` разрешается от рабочей директории.

Альтернативный запуск в браузере:

```powershell
.\.venv\Scripts\python.exe -m notebook lab1.ipynb
```

Для Linux/macOS: создать окружение командой `python3 -m venv .venv`,
использовать `.venv/bin/python` вместо `.venv/Scripts/python.exe`.
Вычисления выполняются на CPU, GPU не требуется.

## Данные

- Bike Sharing: https://www.kaggle.com/datasets/marklvl/bike-sharing-dataset
- Spaceship Titanic: https://www.kaggle.com/competitions/spaceship-titanic/data

Для повторного запуска включены ранее предоставленные `day.csv` и `train.csv`.
В папке `data` также сохранён конкурсный `test.csv`. Он не используется при обучении, предобработке, выборе настроек и локальной оценке моделей.

## Эксперименты

Seed: 42. Разбиение выполняется самостоятельно.

- Bike Sharing: train 438 / validation 146 / test 147.
  Из X исключены `casual`, `registered`, `instant`, `dteday`.
  Числовые признаки стандартизированы, категории кодируются one-hot.
- Spaceship Titanic: train 5215 / validation 1739 / test 1739.
  Стратификация по Transported. Исключены PassengerId и Name.
  Cabin разделён на палубу, номер, сторону; числовые пропуски заполнены медианами;
  расходы преобразованы через log1p. Категории кодируются one-hot с Unknown.

Параметры предобработки определяются только по train. Настройки выбираются по validation.
Test используется для итоговой оценки. После выбора настроек модель не переобучается
на объединении train и validation.

| Модель | Выбор настроек | Результаты на test |
|---|---|---|
| Linear Regression | lr=0.01, 1000 эпох, критерий validation RMSE | MAE=555.9205, RMSE=723.3595, R²=0.8424 |
| Mean baseline | Среднее y_train | MAE=1511.9331, RMSE=1823.2899, R²=-0.0011 |
| Logistic Regression | lr=0.1, 3000 эпох, критерий validation LogLoss; порог 0.5 | Accuracy=0.7769, Precision=0.7681, Recall=0.7979, F1=0.7828, LogLoss=0.4788 |
| Majority baseline | Класс 1; постоянная вероятность равна доле класса 1 на train | Accuracy=0.5037, Precision=0.5037, Recall=1, F1=0.6700, LogLoss=0.6931 |

Confusion matrix логистической регрессии: TN=652, FP=211, FN=177, TP=699.

Ограничения: случайное разбиение Bike Sharing не проверяет прогнозирование будущего
периода; разбиение Spaceship Titanic по пассажирам не изолирует целые группы.
Полное one-hot кодирование вместе с bias создаёт зависимые столбцы:
градиентный спуск допустим, но отдельные коэффициенты могут быть неединственными.
Неизвестная категория Bike Sharing кодируется нулями в соответствующем блоке;
в Spaceship Titanic используется Unknown. Вес категории, не представленной на train,
не может быть обучен на реальных примерах такой категории.

## Последняя ячейка

Это независимая проверка вычисления метрик, а не повторное обучение готовой модели sklearn.
`assert_allclose` сравнивает значения с допусками для вычислений с плавающей точкой.
`assert_array_equal` проверяет полное совпадение confusion matrix.
При расхождении возникает AssertionError; при успехе выводится таблица сравнения и сообщение.
Совпадение метрик само по себе не доказывает корректность всей модели и отсутствие утечек.
